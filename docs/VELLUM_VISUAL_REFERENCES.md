# Vellum visual references

An inventory of the visual assets and references that shape Vellum, so a future session can understand
the visual direction without the conversations that produced it. The rules themselves live in
`docs/DESIGN_SYSTEM.md`; the identity is summarised in `docs/VELLUM_VISION.md` §5.

Audited 2026-09-15 across every tracked file and the whole git history.

**Kind**: *requirement* — the implementation is the reference and future work must match it;
*inspiration* — informs direction but is not to be copied; *vendor* — third-party, not a Vellum design
decision; *external* — shaped the direction but is not stored in the repository (see the last sections).

## What the repository does not contain

Recorded explicitly so no one assumes they exist:

- **No mockups, concept images, mood boards, design screenshots or generated design references** are
  stored anywhere in the repository or its git history.
- **No product screenshots** are stored. The end-to-end suites and `node tools/cdp.mjs shot <png>` write
  screenshots to temporary folders only.
- **No Liu font file**, licence or metadata (a planned document-editing font, not a UI or brand font; see
  Vision §4.4), and no other bundled font besides Jost and pdf.js's standard fonts.
- **No brand guide** beyond `DESIGN_SYSTEM.md` and the in-code icon and illustration above.

## External references (conversation only)

| Reference | Where it exists | What it informed | Kind |
|---|---|---|---|
| Visual reference images shared in past design conversations (their exact contents can't be verified from the repository) | only in past ChatGPT/Claude conversations; **not in the repository**, not retrievable from it | the visual direction as recorded in `DESIGN_SYSTEM.md` and Vision §5 (paper, clay, clear glass, warm paper, premium desktop workspace) | external |

These references remain part of Vellum's design direction, but they can't be inspected here, so nothing
may be attributed to them beyond what the design system already records. No file, path or description of
their contents is invented. Until they are supplied, the implemented UI, `DESIGN_SYSTEM.md` and the assets
listed above are the only authoritative visual references.

## Adding a reference

1. Put the file in the repository (for design references, `docs/references/`, which doesn't exist yet
   and is created with the first real reference; for app assets, where the app loads them from). Never
   link to an internet-hosted image. When an external reference above is supplied, move its row into the
   repository tables.
2. Add a row here: path, what it shows, which decision it informs, and whether it is inspiration or a
   requirement.
3. If it changes a rule, update `DESIGN_SYSTEM.md` in the same change.
